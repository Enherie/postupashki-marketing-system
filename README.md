# Поступашки — Telegram-бот измерительной системы

Рабочий MVP, который объединяет в одном боте почти всю measurement-архитектуру
кейса: продажи курсов, deep-link трекинг рекламы, промокоды, attribution,
ROMI и прогноз — прямо в Telegram, без отдельного сайта.

## Что реально, а что демо

| Часть | Статус |
|---|---|
| База данных (users/touches/ad_links/promocodes/orders) | **реальная**, живая SQLite |
| Каталог курсов, deep-link трекинг, промокоды | **реальные**, работают через сам бот |
| Attribution (last-touch) и ROMI | **реальный расчёт** по накопленным данным |
| Оплата курса | **ДЕМО** — кнопка "Оплатить" сразу пишет заказ в базу, без платёжного провайдера. Для продакшна сюда встраивается Telegram Payments API / эквайринг; формат заказа (`orders`) не изменится |
| Импорт `base.xlsx` и любых других таблиц продаж | **реальный**, работает и с чужой схемой колонок |

## Архитектура и как это соотносится с кейсом

```
ad_link (канал, cost) --deep-link--> touch --last-touch--> order --> ROMI
                       \--промокод--/
```

- **Marketing data model / user stitching** — реализованы буквально: `user_id` — это настоящий Telegram id, а не суррогат, поэтому проблема сшивки пользователя между системами решена тем способом, который мы обсуждали как самый надёжный: deterministic stitching через `bot_start`.
- **Tracking внешней рекламы** — `/newlink` создаёт `campaign/placement/creative` с уникальным кодом и готовой ссылкой `t.me/<bot>?start=<код>`.
- **Собственный канал / промокоды** — активация промокода тоже пишется как `touch` (с пометкой `source='promo'`) — это закрывает случай, когда раздать кликабельную ссылку нельзя (например, код назвали в прямом эфире).
- **Attribution model** — реализован `last_touch` с окном 7 дней (`config.ATTRIBUTION_WINDOW_DAYS`) — обоснование то же, что мы обсуждали: это не impulse-purchase продукт, пользователь может думать несколько дней.
- **ROMI** — `/romi` считает по-честному: `(attributed_revenue − cost) / cost`, только для ad_link с известным cost.
- **Прогноз** — `/forecast` сравнивает naive / seasonal_naive / moving_average_7 бэктестом на последних днях, как в кейсе — простой baseline вместо переусложнённой модели.
- **Что не реализовано и почему это честно** — **incrementality** (ROMI_inc) отдельно не считается: для него нужен A/B/holdout эксперимент, которого система пока не проводит. То, что считает `/romi` — это `ROMI_attr`, и это явно написано в коде, не выдаётся за причинный эффект.

## Установка

```bash
pip install -r requirements.txt
cp .env.example .env
# откройте .env и впишите: BOT_TOKEN, BOT_USERNAME, ADMIN_IDS (свой telegram user_id)
```

Узнать свой `user_id` — написать любому боту вроде `@userinfobot`.

**Важно про токен:** если ваш токен от BotFather когда-либо был кому-то показан (переписка, чат, скриншот) — перевыпустите его: `@BotFather → /mybots → ваш бот → Bot Settings → Revoke current token`. Старый токен сразу перестанет работать, новый впишите в `.env`.

### (опционально) Забэкфилить исторические продажи

```bash
python import_history.py data/base.xlsx
# для таблицы с другими названиями колонок:
python import_history.py other_shop.csv --student-col customer_id --amount-col price --course-col product --time-col purchased_at
```

Импортированные заказы всегда попадают в `organic/unknown` — у истории нет данных о касаниях, и это не подделывается.

### Запуск

```bash
python bot.py
```

Бот начнёт polling. Напишите ему `/start` от своего аккаунта — если ваш `user_id` есть в `ADMIN_IDS`, вам сразу доступны админ-команды.

## Команды

**Пользователь:** `/start [код]` → каталог курсов → тариф → демо-оплата; кнопка "У меня есть промокод"; "Мои покупки".

**Админ (только для id из `ADMIN_IDS`):**
- `/newlink Канал А | 25000 | native_post | creative1 | комментарий` — создать размещение, бот вернёт готовую ссылку для рекламы
- `/links` — список всех размещений со ссылками
- `/newpromo SALE10 10 <код_ссылки>` — создать промокод (привязка к ссылке опциональна)
- `/stats` — общая сводка: пользователи, касания, заказы, % organic
- `/romi` — ROMI по каждому размещению
- `/forecast` — baseline-прогноз с честным backtest
- отправить боту файл `.xlsx`/`.csv` — импортирует его как исторические продажи (колонки по умолчанию как в `base.xlsx`; для других названий — используйте `import_history.py` с флагами)

## Тесты

```bash
python tests/test_core.py
```

Проверяет БД, attribution (включая окно и dedupe промокодов) и импортёр — без Telegram (для этого не нужен ни токен, ни сеть). Реальную отправку сообщений в Telegram эти тесты не проверяют — это можно увидеть только запустив бота вживую.

## Структура проекта

```
config.py       — токен из .env, каталог курсов, окно атрибуции
db.py           — схема SQLite + CRUD, без зависимости от Telegram
attribution.py  — last-touch attribution + ROMI поверх БД
importer.py     — импорт произвольной таблицы продаж (настраиваемые колонки)
keyboards.py    — inline-клавиатуры (минималистичный стиль)
bot.py          — пользовательские сценарии
admin.py        — админ-команды ("панель управления" прямо в Telegram)
import_history.py — разовый CLI-импорт истории
tests/test_core.py — тесты бизнес-логики
```

## Честные ограничения

- Оплата — демонстрационная (см. таблицу выше).
- Эта песочница, в которой собирался код, не имеет доступа в интернет, поэтому реальный live-опрос Telegram API (`bot.infinity_polling()`) здесь не запускался и не тестировался — только сама бизнес-логика (`db.py`, `attribution.py`, `importer.py`) и обработчики (`bot.py`, `admin.py`) через подмену Telegram-слоя. Перед защитой стоит один раз руками прогнать основной сценарий вживую.
- `/forecast` даёт разумную оценку только при достаточной истории (≥14 дней) — при малом количестве данных явно об этом пишет, а не выдаёт натянутую цифру.
